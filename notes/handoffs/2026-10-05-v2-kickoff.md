## 终端与 Textual 的调查细节（ADR-0006 只记了决定，没记这些）

- **Textual 8.2.8**（`pyproject.toml` 锁的）。`ctrl+enter` **不在它的 Keys 枚举里**；传统终端把 ctrl+enter 发成 `0x0D`，与 `Enter` 同一个字节。
- **收得到** ctrl+enter 的终端：kitty / ghostty / foot / alacritty / iTerm2 ≥ 3.5。**收不到**：tmux（`extended-keys` 默认 off，且默认格式是 Textual 解析不了的 xterm 格式）、WezTerm（`enable_kitty_keyboard` 默认 false）、gnome-terminal（VTE 的 kitty 协议支持至今未合并）、xterm。
- 用户自己用的终端：**kitty/ghostty 系，以及 Windows Terminal / VS Code 集成终端**（两个都选了）。
- 用户拍板的方案：关掉推送 `TEXTUAL_DISABLE_KITTY_KEY=1`。这个环境变量是真的——`textual/constants.py:116` 定义，`_xterm_parser.py:424` 与 `drivers/linux_driver.py:285` 都会检查。
- **IME bug**：textual#6721（8.2.8 上已复现：一次上屏 11 个汉字变乱码、4 个正常）。同批不可靠的还有 #6663（`alt+enter` 塌缩成 `enter`）、#6612（`shift+backspace`）。
- **`space` 的坑**：`Input`/`TextArea` 拿到焦点时 `space` 被当字符吞掉，app 级绑定**静默失效**。所以完成键只在任务列表页有效——那一页没有输入框抢焦点。

## 风险与未决

- **spec 的 Further Notes 列了 5 条「未经验证」**：删除清单时里面的任务会怎样、普通更新能否单独取消完成、`kind` 是 NOTE 的清单、项目组在真实账户里的行为、服务端自动补 `startDate`。实现时**不要当已知**。
