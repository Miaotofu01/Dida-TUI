## What to build

任务列表页按 `space` 在**完成**与**取消完成**之间切换，并立即推送。

- **完成**走文档化的完成端点。
- **取消完成**走批量更新端点的 `update` 数组带 `status: 0`。这条路径官方文档**一字未提**，是实测确认的：批量更新带 `status: 2` 能把任务完成，带 `status: 0` 能把已完成的任务改回未完成。批量更新是**合并语义**——只发 id、projectId、status，标题 / 描述 / 备注 / 优先级全部保留。**不要因为「文档没写」就把它当成不该存在的用法删掉。**
- 完成或取消完成后给一个短暂的视觉反馈，让用户知道这一下生效了。
- `space` **只在任务列表页生效**：输入框拿到焦点时它会被当字符吞掉、app 级绑定静默失效，而这一页没有输入框抢焦点。输入框存在时一律走 `enter` 提交。

取消完成之后，**本地不能再把它算作已完成**，即使它的完成时间戳还在。

## Acceptance criteria

- [ ] 任务列表页按 `space` 把未完成任务标记完成，并立即推送
- [ ] 再按 `space` 把已完成任务改回未完成，并立即推送
- [ ] 取消完成打到批量更新端点且带 `status: 0`
- [ ] 批量更新只发 id、projectId、status；其余字段不因这次取消完成而改变
- [ ] 完成或取消完成后有短暂的视觉反馈
- [ ] 取消完成后本地立刻不再把它算作已完成，即使完成时间戳还在
- [ ] `space` 在输入框有焦点时不影响输入（该打空格就打空格）
- [ ] 一个测试完整走通「按 `space` → 假后端收到完成调用」，另一个走通取消完成那一路
- [ ] 有测试钉死「取消完成」的请求形状（端点 + `status: 0`）
