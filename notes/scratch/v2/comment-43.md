**给这张工单补一条渲染规则**（用户在视觉原型上定的，直接落在你这一页）。

## 列表截断，详细页换行

用户的原话：**「进入任务详细页的内容需要自动换行，其他的部分保留截断」**。

所以：

- **清单列表页与任务列表页继续截断**（按单元格裁，带省略号 `…`）。
- **任务详细页的字段值自动换行**——标题、描述、备注都要能换行读完。

理由很直接：列表里的任务是一行一条、要能扫视，所以宁可截断；而详细页存在的意义就是「来这里读完整的」。截断放错地方就会变成「哪儿都读不全」。

## 这条规则的实现后果（**你这一页要承担**）

详细页的字段行**不再是固定一行**——一个长描述会占多行。于是：

1. **光标仍然在字段之间移动，不是在行之间移动**：`j` / `k` 一次跳一个字段，永远不停在折行块内部。
2. **光标定位与滚动不能再用「一个字段 = 一屏一行」的假设**。需要一个**屏幕行偏移表**（每个字段按
   `ceil(单元格数 / 可用宽度)` 算高度，再前缀和），`place_bar()` 与 `scroll_cursor_into_view()` 都要按它算。
   原型里原来那套（`offset.y = cursor - len(row_views)`）在换行下是错的。
3. **选中样式要盖住整个折行块**，不能只盖第一行，否则看起来像只盖了半个字段。
4. 窄终端下（≥30 列）也要成立——spec 有一条「我要在窄终端里也能用」。

## 已经在原型里踩到并修掉的两件事，别重犯

- **`animate(...)` 必须带 `on_complete`**：原型的滑动光标条漏了它，于是动画结束后永远停在落点那一行上，
  把该行的 `❯` 标记盖掉——用户报的就是「上下键选中的行会消失」。原因很隐蔽：那根条在 v1 里的内容是
  **两个空格 + 透明背景**，但它是个满宽 `Static`、占满一行，所以盖掉的正是光标行的前两格，也就是标记位。
- **截断的优先级也是错的**（原型 30 列实测 `~ 回邮件给 … 3 天前`：标题被砍成四个字，而截止时间 `昨天 18:00`
  一格不少）。列表页的丢弃顺序应该是**标签 → 重复/提醒标记 → 截止时间 → 最后才截标题**。这条归列表页（#37），
  但你这一页的换行不要在宽度不够时退化回「标题先被砍」。
