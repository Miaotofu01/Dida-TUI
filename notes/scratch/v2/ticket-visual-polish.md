## What to build

视觉地基落地时，界面上只有五个面里的三个（清单列表页、任务列表页、详细页的接缝），而浮层、字段编辑、动作反馈都还没建。**这张工单是等界面完整之后的收尾打磨**——地基定的是语言，这张定的是它在每一个真实表面上都成立。

它必须在 #35–#48 全部落地之后做，理由不是礼貌：那些工单会各自往界面上加东西（任务行、视图行、清单与视图的浮层、详细页字段编辑、分层帮助、动作键与 toast），每加一处就有一次「这一处该用哪个语义 token」的机会，而这个机会只有看到成品才能判断对错。

要做的：

**1. 逐面对账。** 五个面（清单列表页 / 任务列表页 / 任务详细页 / 两个浮层）逐个看，与 `tui/theme.py` 对账，把地基之后新增的每一处都收进语义 token。任何在页面里写死视觉值的地方都是这次要收掉的债。

**2. 逾期标红接上。** #37 会给读模型加 overdue 位；地基只留了 token。这次把 `overdue` token 真正接上——**这是 spec 的硬要求**（「逾期任务标红」），而它今天做不到（`TaskItem` 没有 overdue 位，TUI 不许判断日期）。

**3. 动效复核手感，尤其是光标。** 地基让光标「选中立即到位、光标条随后追上」。这次要在真终端里**连续快按 `j`** 复核：如果手感粘、或者追赶条在快速连按时看起来在跳，就调时长或降级成高亮淡入。理由：这个 app 的定位是「一次按键的手感比可撤销性更值钱」，动效不能赢过手感。

**4. 窄终端与中文长标题。** 地基修了截断与字形宽度，这次在 60/80/120 三档宽度、以及带**超过四个汉字**的中文标题下逐面复核对齐与滚动。

**5. 反馈文案与时长。** toast 的措辞（完成 / 取消完成 / 推送失败 / 覆盖告知）与停留时长定稿；「待推送非零时高亮」在跟随主题之后仍然看得见。

## Acceptance criteria

- [ ] 五个面逐个与 `tui/theme.py` 对账过，**没有一处在页面或浮层里写死视觉值**
- [ ] 逾期任务标红已接上 `overdue` token（#37 的读模型到位之后）
- [ ] 光标动效在**连续快按 `j`** 下复核过，手感不粘；不合格就降级，并说明降级到了什么
- [ ] 60 / 80 / 120 三档宽度下，含长中文标题（>4 汉字）的行不折行、不破对齐、滚动正常
- [ ] toast 措辞与时长定稿；「待推送非零」的高亮在跟随主题后仍然明显
- [ ] README 的截图与帮助文案与成品对账（地基落地时它们只反映地基那一版）
- [ ] `uv run pytest` 全绿；真 pty 下三页 + 浮层 + toast 全部实际渲染过
- [ ] 以「地基定的语言在每个面上都成立」为准绳逐条复核，而不是以「测试绿了」为准
