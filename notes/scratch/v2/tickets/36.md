## What to build

用户能建自己的视图（「高优先级未完成」这类），并且**改得动、删得掉**。视图 = 一组过滤条件 + 一个名字。过滤维度：清单范围（多选）、截止时间区间（相对逻辑日表达，例如「今天到期」「最近七天」「无日期」）、优先级（多选）、标签（多选）、完成状态。

- 按 `n` **先问一句「清单还是视图」**——这两种东西后面完全是两回事。
- 选视图后进浮层填名字与条件。**清单的建 / 改表单与视图的条件表单是同一个浮层**，按选中行的类型决定字段（清单那张工单会用到同一个浮层，谁先落地谁把浮层壳子搭出来）。
- 按 `e` 改当前视图的条件，改完立刻生效。
- 按 `d` 一次 y/n 确认后删除。**删视图不删除任何任务**——视图只是过滤条件。

视图定义存**本地库**，不存配置文件：那是放 token 的文件，不该为了改一个过滤条件去手写凭据。求值在本地对全量缓存做，不走服务端的查询接口——那个接口的日期区间过滤的是开始时间而不是截止时间，而且硬顶 200 条、没有分页，根本表达不了「今天到期」。

浮层里要**如实说清**：自定义视图只存在这台机器上，手机上、网页版上没有它，换台机器就没了。这是 API 的能力上限，不是实现疏漏——不要试图把视图同步上去，那条路不存在。

## Acceptance criteria

- [ ] 清单列表页按 `n` 先被问「清单还是视图」
- [ ] 选视图后能在浮层里填名字与过滤条件：清单范围、日期区间、优先级、标签、完成状态
- [ ] 视图定义落本地库，不写进配置文件
- [ ] 浮层里明确告知视图只存在本机
- [ ] 建好的视图出现在清单列表页，`enter` 进去看到过滤后的任务
- [ ] 按 `e` 能改条件，改完立刻生效（不必重进这一页）
- [ ] 按 `d` 一次 y/n 确认后删除该视图
- [ ] 删除视图不删除任何任务
- [ ] 能建出「高优先级未完成」和一个「最近完成」的例子（后者按完成状态与完成时间筛）
- [ ] 求值走纯函数那条路径，与内置视图同一份实现
