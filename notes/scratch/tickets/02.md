## What to build

首次使用者粘贴个人 API Token 时不会被坑：token 在写入磁盘**之前**先被验证一次（至少能成功列出清单），验证不过就不落盘。验证不过或日后失效时，用户看到的是「凭据失效，请重新粘贴」这样的明确指引，而不是一个笼统的网络错误。

配置文件落在 `~/.config/dida-tui/config.toml`，权限 0600，存 token、逻辑日边界、刷新与推送开关、已完成区窗口；文件缺失时生成默认配置。配置 schema 与 `day_end` 的取值约束见 spec 的「配置 schema」（`00:00`–`24:00`，可解析成整分钟）。

## Acceptance criteria

- [ ] 首次运行会提示粘贴 token，且只有在一次「列清单」调用成功之后才写入磁盘
- [ ] 验证失败时不把 token 写入磁盘
- [ ] 已配置 token 的使用者启动时不被再次询问
- [ ] 凭据失效被表达成明确的认证失败并引导重新粘贴 token，而不是笼统的网络错误
- [ ] 配置文件权限是 0600；文件缺失时生成默认配置
- [ ] `day_end` 取值在 `00:00` 到 `24:00` 之间且能被解析成整分钟，否则被拒绝
