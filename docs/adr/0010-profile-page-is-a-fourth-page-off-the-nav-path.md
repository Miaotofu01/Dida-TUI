# 个人主页是第四种页面，不在导航路径上

新功能「个人主页」要在界面上多出一块整屏的东西：账号绑定、热力图、日 / 周 / 月 / 总 已完成数、未完成任务数、逾期任务数。

`GLOSSARY.md` 在此之前把「页面」定义成**恰好三种形态**（「app 里一共就这三种页」），把「导航路径」定义成**最多三级**（`→` 压入、`←` 弹出）。加一个主页就是在动这两个定义，所以先把话说清楚：**它是第四种页面，但不进那条路径。**

## 一、决定

- **页面一共有四种**：三种在导航路径上（清单列表页 → 任务列表页 → 任务详细页），**个人主页在路径之外**。
- **进入与退出**：从清单列表页进入（`A`），`←` / `esc` 回原处。
- **顶栏**：在个人主页上，顶栏显示「个人主页」作为当前页，**不画路径**。顶栏的职责是「你在哪」（`GLOSSARY.md` 的「顶栏」），而这一页不在任何一条路径上——硬画就会出现「清单列表 ▸ 任务列表 ▸ 个人」这种并不存在的关系。
- **`h` 帮助**：给这一页单独一层键位（`keys.py` 的 `LAYER_*`），与另外三页同构。

## 二、为什么不选另外两条

**为什么不做成导航路径的第四层？** 因为那会让顶栏开始说假话。`→` 的语义是「这一行里面还有东西」：清单里有任务、任务里有字段。个人主页不是任何一行的「里面」——它是对**整个账号**说的。真把它画成第四层，顶栏就会出现一个用户无从理解的嵌套关系，而且「从任务详细页进入个人主页」会变成一个必须回答的问题（答什么都别扭）。

**为什么不做成一个覆盖层？** 覆盖层在这个仓库里是「短交互 + 提交/取消」（`FormOverlay`、`ConfirmOverlay`、`MessageOverlay`），拿来做一整屏的统计与热力图，等于把一个页面硬塞进一个弹窗：键位、退场语义、`←` 的含义全都要另说。**换绑那一步仍然是覆盖层**——那才是短交互。

## 三、代价

- `GLOSSARY.md` 的「页面」「导航路径」两条定义要改（已改）。
- `tests/test_architecture.py` 与 `keys.py` 的层表要多一层；`h` 帮助、顶栏、`←` 的退场都要各加一处判断——**每一处漏掉都只表现为「按了没反应」**，这是这一页最主要的回归面。
- 这一页是**只读**的（除了换绑），所以它不需要向引擎要任何写能力；统计与热力图另开一张票（见 ADR-0011 末尾的分票）。
