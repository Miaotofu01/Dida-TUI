# 从「今日执行台」转为通用终端客户端

v1 的定位是「把今天该做什么这一屏做到极致」：三栏、清单只是带角标的装饰、不能进入任何清单、所有任务汇总进一张按逻辑日分区的表。真实使用后判定**不可用**——用户要看的是滴答清单网页版同款的任务视野：能选清单、能进入清单、能往指定清单加任务。因此 v2 改成通用客户端：一栏、三层页面（清单列表 → 任务列表 → 任务详细页），启动落在清单列表，「今天」降级成三个内置视图之一。

## Consequences

- v1 的读模型整体作废，不是被扩展：`TodayView` 与它硬编码的三个分区（逾期 / 今日 / 收集箱无日期）都要拆掉，同步引擎的读入口必须重写。换 TUI 是不够的。
- 一并作废的 v1 能力：一行速记语法（`a`）与它背后的整个日期解析器、优先级循环键 `p`、`/` 过滤、右栏常驻详情、三栏响应式降级。这些不是被延后，是**确定不做**。
- 保留的 v1 资产：API 客户端、SQLite 存储、重试队列与「待推送改动豁免」、逻辑日、凭据引导与验证、以及「写操作立即推送」。
- 「逻辑日」没有随定位一起消失：`day_end` 继续作用于**所有**与日期有关的判断（今天 / 逾期 / 顺延），不是只作用于「今天」这一个视图。
- 「今天」这个视图**包含逾期任务**（逾期置顶、标红，下面才是今天到期的）。所以「今天」不是一个干净的 dueDate 区间，视图定义要写清这一点。
