# Dida TUI

一个终端里的滴答清单客户端：在终端里浏览**全部**清单与任务、直接新建和编辑，写操作立即推送到滴答清单。

命令是 `dida`，Python 3.12 + Textual，主目标是 Linux。

**一栏，三层页面**：清单列表页 → 任务列表页 → 任务详细页，`→` 进入下一层、`←` 退回上一层。
启动落在清单列表页；「今天」只是三个内置视图（今天 / 最近七天 / 所有）之一，不再是整个 app 的定位
（[ADR-0004](docs/adr/0004-terminal-client-not-today-console.md)）。它取代了 v1 那个三栏的「今日执行台」——
v1 的三栏布局、`Tab` 焦点切换、清单浮层与窄屏降级都已经删掉：一栏的布局天然不需要降级。

下面这三屏是把 `FakeBackend`（内存假后端 + 真引擎）跑起来**真的渲染出来**的，不是画的：

```
❯ ▣ 收集箱  2
  ▸ 今天  6
  ▸ 最近七天  4
  ▸ 所有  8
  ★ 我的一天  1
  ☰ 工作  3
  ☰ 生活  2
  ☰ 学习  1

已同步 12:00 · 待推送 2 · 逻辑日 03-14
 ↑ 上一行  ↓ 下一行  h 当前这一层的键位  r 手动同步  o 在浏览器里打开当前任务  q 退出  → 进入这一行
```

三种行用**前缀字符**区分（不靠颜色单独承担）：`▣` 收集箱 · `▸` 内置视图 · `★` 自建视图 · `☰` 真实清单。
每行右边是这个容器的未完成条数；真实清单按项目组归拢，项目组是不可进入的小标题；`kind` 是 NOTE 或者
没有写权限的清单会被标出来，且进不去。

```
  ── 工作 ──
❯ 交季度报告
  写周报
  把 Q1 的数字对齐财务口径

已同步 12:00 · 待推送 2 · 逻辑日 03-14
 ↑ 上一条  ↓ 下一条  h 当前这一层的键位  r 手动同步  o 在浏览器里打开当前任务  q 退出  → 任务详细页  ← 退回清单列表页
```

```
❯ 标题  交季度报告
  描述  把 Q1 的数字对齐财务口径
  备注  下周一前发出去
  清单  工作
  截止  3 天前
  优先级  高
  标签  #工作 #季度
  子任务  ☑ 收集数据  ☐ 写结论
  提醒  提前 9 小时
  重复  RRULE:FREQ=DAILY;INTERVAL=1
  以上只读：子任务、提醒、重复规则要回官方客户端改

已保存
已同步 12:00 · 待推送 2 · 逻辑日 03-14
 h 当前这一层的键位  r 手动同步  o 在浏览器里打开当前任务  q 退出  enter 编辑这个字段  esc 结束编辑（保存）  ← 退回任务列表页
```

状态栏常驻三样东西：已同步时刻、待推送数量（**非零时高亮**）、当前逻辑日。

## 安装

还没发布到 PyPI，从源码装：

```bash
git clone git@github.com:Miaotofu01/Dida-TUI.git
cd Dida-TUI
uv tool install -e .
dida
```

不想装成全局命令，就在仓库里 `uv run dida`。需要 Python 3.12+ 和一个真终端（只用终端 16 色，不需要真彩）。主目标是 Linux，Windows 与 macOS 不提供打包。

## 第一次运行：粘一个 Token

1. 在滴答清单网页版打开「设置 → 账户 → API Token」，复制那串 token。
2. 第一次运行 `dida` 会生成 `~/.config/dida-tui/config.toml`（权限 0600），并提示你粘贴——输入不回显。
3. token 只在一次成功的「列清单」调用**之后**才落盘，所以这一步需要联网。粘错了、网断了都**不会碰你的配置文件**，重跑一次 `dida` 再来即可。

只用个人 API Token：没有 OAuth，没有回调地址，也没有刷新令牌。

## 键位

每一层只列**当前这一层真能按的**键：

| 到处都能按 | |
|---|---|
| `j` / `k`（或 `↑` / `↓`） | 上下移动光标 |
| `→`（`right`） | 进入下一层 |
| `←`（`left`） | 退回上一层 |
| `h` | 当前这一层的键位帮助 |
| `r` | 手动同步：全量刷新 + 推待推送改动 + 拉已完成流 |
| `o` | 在浏览器里打开当前任务 |
| `q` | 退出（还有没推上去的改动时会先拦一下） |

| 清单列表页 | |
|---|---|
| `j` / `k` / `↑` / `↓` | 在清单、视图、收集箱之间移动 |
| `→` | 进入这一行（清单、内置视图、自建视图）；`←` 在这里什么都不做 |

| 任务列表页 | |
|---|---|
| `j` / `k` / `↑` / `↓` | 在任务之间移动 |
| `→` | 进入这条任务的详细页 |
| `←` | 退回清单列表页（光标还原到进来的那一行） |

| 任务详细页 | |
|---|---|
| `j` / `k` / `↑` / `↓` | 在字段之间移动（标题 / 描述 / 备注 / 清单 / 截止 / 优先级 / 标签） |
| `enter` | 编辑当前字段（标题、描述、备注；多行框里 `enter` 是换行） |
| `esc` | 结束这次编辑（改动已经生效，没有「取消」）；字段列表上它什么都不做 |
| `←` | 退回任务列表页 |
| `←` / `→`（编辑中） | 在文字里移动光标 |

编辑标题 / 描述 / 备注时，`←` / `→` 归输入框（在文字里移光标）；单档挑选器里它们仍是「上一档 / 下一档」，多选那一格是 `↑` / `↓` 移动、`space` 打勾。

应用内 `h` 看到的那份帮助由绑定表长出来（[src/dida/tui/keys.py](src/dida/tui/keys.py)，按层分开）——
[tests/test_keymap.py](tests/test_keymap.py) 盯着两者不许漂移，所以绑定表漏了哪个键，测试会先红。

**还在补的键**（spec 的键位表里已经定稿，落在后面几张工单上，现在按下去还没有反应）：清单的 `n` 新建 /
`e` 改 / `d` 删（#42，视图的建改删是 #35 / #36）、任务列表页的 `space` 完成 ↔ 取消完成（#38）、`n` 新建（#39）、
`d` 删除与 `g` / `G` 顺延（#40）、任务详细页的截止时间与挑选型字段（#44 / #45）。

## 配置

`~/.config/dida-tui/config.toml`（0600；路径写死，不认 `XDG_CONFIG_HOME`）。缓存库在隔壁 `~/.config/dida-tui/cache.sqlite3`。

| 键 | 默认 | 含义 |
|---|---|---|
| `token` | 无 | 个人 API Token，只在验证成功后落盘 |
| `day_end` | `"24:00"` | 逻辑日的结束时刻。见下 |
| `refresh_on_start` | `true` | 启动后自动全量刷新一次 |
| `push_on_change` | `true` | 改动立即推送；关掉就等下一次 `r` 或周期泵 |
| `completed_window_hours` | `24` | 「已完成 N 项」往回看多久 |

`day_end` 是这个 app 最值钱的一个配置。默认 `24:00`——逻辑日就是自然日；配成 `"04:00"`，凌晨 2 点仍属于你还没睡的那个前一天，「今天」因此不会在你熬夜时翻页。只接受 `HH:MM`、必须是整分钟，`24:00` 会折成规范形式 `00:00`（两者都表示不偏移）。改完要重启才生效。

## 同步与冲突

- **启动先画本地缓存**，网络从来不挡第一屏。
- **网络层永远全量**。滴答清单 API 没有 changed-since、没有可用的条件请求、也没有 webhook；所以每次刷新都是逐清单把未完成任务全拉回来，再在本地比对，只写变化——增量是本地存储层的概念，不是网络层的。把逐清单全量「优化」成日期窗口会静默漏掉「日期在很久以后、但刚刚被改过」的任务，那正是被明确禁止的改动（[ADR-0001](docs/adr/0001-full-refresh-and-local-diff.md)）。
- **改动立即推送**。失败就留在重试队列里，按 2 秒 × 2ⁿ 退避，最多 5 分钟一次；状态栏常驻显示待推送数量，推成功自己归零。退出**不会丢**：队列落在本地库里，下次打开 `dida` 接着补推。
- **冲突归服务端**。服务端字段值覆盖本地，除非这个字段上有还没推成功的改动（那一笔豁免，否则一次刷新就会撤销你刚做的操作）。覆盖发生了会告诉你覆盖了几处（[ADR-0002](docs/adr/0002-immediate-push-irreversible-complete.md)）。
- **完成可以来回**。完成走文档化的完成端点；**取消完成**走批量更新（`task/batch` 的 `update` 带 `status: 0`）——官方文档一字未提，是本项目实测确认的（[ADR-0002](docs/adr/0002-immediate-push-irreversible-complete.md) 记着实测过程）。所以完成键是一个**开关**，不是单向门。
- **删除不可恢复**。API 里没有回收站、没有 undelete、没有「已删除」列表，所以删除前会问一次，文案只说真话——连「删掉这个清单，里面的任务会怎样」都如实说不知道，因为文档没写。
- **收集箱那一行是客户端补的**：服务端的清单索引里没有它，而它的任务带着一个每账户不同的 `projectId`（`inbox` 只是请求侧的别名）。归类、分组、计数一律按服务端返回的那个 id 走，拿字面量 `inbox` 去比对会一条都对不上。

## 已知限制（这一版还没做完的地方）

界面正在按 [issue #30](https://github.com/Miaotofu01/Dida-TUI/issues/30) 的工单一张一张替换。#34 之后能用的是
**骨架**：三层页面进得去、退得回，缓存照读、同步照跑，各层的动作键与写路径还没接上。

1. 清单列表页只能看和进：新建 / 改名 / 删除清单与视图还没接上（#35 / #36 / #42）。
2. 任务列表页只能看和进详细页：完成、取消完成、新建、删除、顺延都还没接上（#38 / #39 / #40）；任务行现在只画标题，优先级标记与人类可读的截止时间归 #37。
3. 任务详细页能改标题 / 描述 / 备注了（#43）；所属清单、截止时间、优先级、标签还只读显示（#44 / #45）。
   只读的还有子任务、提醒与重复规则——那三样要回官方客户端改（详细页上就写着这句话）。
4. 「最近 7 天完成」的窗口现在还是 24 小时（配置里的 `completed_window_hours`），#37 改成 7 天。

v2 不做自然语言日期输入（v1 的「一行语法」与它背后的日期解析器已随这次重写删除）：新建只填标题（#39），
改截止时间走结构化选择器（#44）。

## 不做什么

「它不复制滴答清单的全部能力」不是一句客套。哪些不做、为什么不做，写在
[issue #30 的 Out of Scope](https://github.com/Miaotofu01/Dida-TUI/issues/30) 里——那是这份代码现在的 spec。
（v1 的 spec 是 [issue #1](https://github.com/Miaotofu01/Dida-TUI/issues/1)，已被 #30 取代，留作历史。）

## 开发

```bash
uv run pytest        # 全绿，400+ 条，约半分钟
```

改代码之前值得先读三份，它们各自只有一份：

- [GLOSSARY.md](GLOSSARY.md)——术语，以及每个术语明确**不**用的同义词。写错词比写错代码更容易被看出来。
- [docs/architecture.md](docs/architecture.md)——模块划分、依赖方向、两个测试接缝。
- [docs/adr/](docs/adr/)——几条已经付过代价的决定。想推翻哪一条，先读完它记的实测证据。

两条硬规则：「现在」只能来自注入的时钟（业务代码不许调 `datetime.now()`），网络只能走注入的传输层。TUI 只许 import `dida.sync.engine` 和自己的 `dida.tui.*`——那是一张允许清单，不是黑名单，[tests/test_architecture.py](tests/test_architecture.py) 用 AST 守着。

测试只断言屏幕文本和假后端收到的调用，不做整屏快照、不碰私有属性。唯一的例外是周期泵那个定时器句柄（[tests/test_pump_teardown.py](tests/test_pump_teardown.py)）：没有纯外部的断言能分清「停了」与「还在跳但恰好没触发」，所以那一条白盒是刻意的。[tests/support.py](tests/support.py) 是唯一触碰 Textual 合成器的地方。

工单与 spec 都住在 GitHub issues 里，用 `gh` 管（约定见 [docs/agents/](docs/agents/)）。每个工单一个标签、一次代码评审，评审记录留在提交信息里。
